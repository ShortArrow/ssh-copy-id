# 既存のssh-copy-idとの差異

[English](compatibility.md) | [設計書](design.jp.md)

更新日: 2026-09-30。合意済みの設計差異の一覧であり、実装済み・検証済みを示すものではない。
差異を上流の不具合や不具合修正とは分類せず、元の設計者の意図も断定しない。

比較対象は[固定した上流の比較基準](design.jp.md#固定した上流の比較基準)とする。
参照コミットと更新方針の詳細は設計書で管理する。

## 合意済みの動作差異

この一覧には比較の要約と詳細へのリンクだけを置く。理由・適用範囲・実現方法・未決事項・
実装および検証状況の詳細は設計書を正とし、ここには重複して記載しない。

| ID | 確認した既存版の動作 | 本プロジェクトの決定 | 詳細 |
| --- | --- | --- | --- |
| D-01 | 確認用接続が成功すると登録対象をスキップする。別の設定済みの鍵が認証した場合もある。 | 別の鍵による認証成功を、登録対象の鍵が登録済みである根拠にしない。他の候補があって確認が不確定なら、警告して登録する。重複が生じ得る。 | [登録対象の鍵](design.jp.md#記録する差異-登録済み確認に使われた鍵) |
| D-02 | `-s` でも `exit` を試行し、特定のSFTP専用エラーメッセージも成功として扱う。 | リモートコマンドや当該メッセージを使わず、SFTPセッション成立で確認する。 | [SFTPでの確認](design.jp.md#記録する差異-sftp方式の登録済み確認) |
| D-03 | SFTPモードは登録先の親を700に設定する。通常モードは一律のchmodを行わない。 | `-t` の既存親ディレクトリの権限を両モードで保持し、権限不足ならエラーにする。 | [任意の登録先の親の権限](design.jp.md#記録する差異-任意の登録先の既存親ディレクトリ) |
| D-04 | 登録用入力の秘密鍵の内容を明示的に拒否せず、`-f` では送信され得る。 | `-f` を含め、秘密鍵入力を送信前にエラーにする。 | [秘密鍵入力の拒否](design.jp.md#秘密鍵入力の拒否) |
| D-05 | 登録用のCRLF入力からCRを明示的に除去しない。 | 送信する入力のCRLFをLFに変換し、接続先の既存内容は保持する。 | [CRLFの正規化](design.jp.md#crlfの正規化) |
| D-06 | 書き込み後はログインコマンドの例を表示し、検証しない。 | `-f` が無い限り、書き込んだ鍵ごとに登録済み確認を再実行し、未検証の鍵を理由付きで報告する。 | [登録後の検証](design.jp.md#記録する差異-登録後の検証) |
| D-07 | 入力先頭のUTF-8 BOMを最初の鍵の行の一部として書く。 | 登録用入力の先頭のBOMを送信前に取り除く。 | [先頭のBOMの除去](design.jp.md#先頭のbomの除去) |
| D-08 | `-s` は取得後の変更を確認せずに編集したファイルをアップロードする。 | `put` の前に `ls -l` を再実行し、サイズか更新時刻が変わっていれば書かずに止める。 | [アップロード前の変更確認](design.jp.md#記録する差異-アップロード前の変更確認) |
| D-09 | `-s` は `get` のエラーをすべて無視して続ける。読み取りに失敗すると、新しい鍵だけのファイルをアップロードし得る。 | 先に `ls -l` で登録先を確認し、ファイル不存在以外のエラーなら書く前に止める。 | [SFTP方式](design.jp.md#sftp方式) |
| D-10 | 不正な行、単独のCR、NULバイトをそのまま追記する。 | 送信前に行番号を付けて拒否する。 | [CRLFの正規化](design.jp.md#crlfの正規化) |
| D-11 | `-t` のパスに引用符があると、接続先の `sh -c` スクリプトが壊れる。 | Unix・Windowsの両接続先でパスをデータとして引用する。 | [既存親ディレクトリ](design.jp.md#記録する差異-任意の登録先の既存親ディレクトリ) |
| D-12 | 接続先を確認せずに `sh` スクリプトを送る。OSのオプションはない。 | 通常方式では書き込み前に接続を1回増やしてシェル系統を判定する。`--target-os` で上書きできる。 | [接続先OSとシェル](design.jp.md#接続先osとシェル) |
| D-13 | どのOpenSSHクライアントでも動く。 | stderrのパターンを試験していないバージョンでは警告する。分類できない出力は確認を不確定にする。 | [接続方式の評価](design.jp.md#接続方式の評価) |
| D-14 | `-x` はシェルの `set -x` のトレースを有効にする。 | `-x` は各クライアントコマンドと接続先スクリプトを実行前に表示する。 | [未決事項](design.jp.md#その他の互換性に関する未決事項) |

## 接続先の差異

Unix系とWindowsの接続先は、プラットフォームが許す限り同じ動作にする
（[設計の立場](design.jp.md#設計の立場)）。この表は揃えられない箇所の一覧で、
各行から決定へリンクする。

| ID | Unix系の接続先 | Windowsの接続先 | 詳細 |
| --- | --- | --- | --- |
| O-01 | すべてのアカウントの鍵を `.ssh/authorized_keys` に置く。 | 管理者の鍵は、既定のサーバー設定では共有の `administrators_authorized_keys` に置く。 | [Windows管理者への登録範囲](design.jp.md#windows管理者への登録範囲) |
| O-02 | 新規作成のディレクトリとファイルは `umask` で700と600になる。 | 新規作成分には `icacls.exe` でアカウント・SYSTEM・Administratorsの最小ACLを設定する。既存のものはどちらも変更しない。 | [権限とサービスの操作範囲](design.jp.md#権限とサービスの操作範囲) |
| O-03 | アカウントのPOSIXシェルが `sh` スクリプトを実行する。 | 既定シェル（`cmd.exe`・Windows PowerShell・`pwsh`）がコマンドを包む。送るのは `EncodedCommand` の1行だけ。 | [Windows向けのリモートコマンド](design.jp.md#windows向けのリモートコマンド) |
| O-04 | 接続先の終了コードがクライアントに届く。 | 既定シェルがPowerShellだと子プロセスの0以外の終了コードは1になる。そのため両接続先とも結果行で結果を伝える。 | [登録結果](design.jp.md#登録結果) |
| O-05 | `-s` はファイルを600にする。親は変更しない（D-03）。 | `-s` はACLを設定できない。正しいACLのディレクトリがあることを前提条件とする。 | [SFTP方式](design.jp.md#sftp方式) |
| O-06 | 接続先の実行時要件はPOSIX `sh`。 | 接続先の実行時要件は `powershell.exe` と、ACLを設定する場合の `icacls.exe`。 | [Windows向けのリモートコマンド](design.jp.md#windows向けのリモートコマンド) |

## 配布時の名前

Linuxパッケージでは `ssh-copy-id-rs` を、同名のマニュアル・シェル補完とともに
インストールし、既存の `ssh-copy-id` と共存させる。Windowsでは `ssh-copy-id.exe` を使う。
パッケージがOpenSSHのコマンドを置き換えたり、エイリアスを自動作成したりしない。
これは上記の動作差異とは別の配布上の決定として扱う。

[共存方針](design.jp.md#opensshパッケージとの共存)

## 一覧の更新方法

合意した差異は固定のIDと詳細な設計判断へのリンクを付け、英語版と本書に追加する。
上流との差異は `D-xx`、接続先の差異は `O-xx` とする。
未採用の提案は[設計レビュー（英語）](design-review.md)に残す。
検証状況は[検証記録（英語）](validation.md)で更新する。設計への合意を、実装済みの根拠にはしない。
