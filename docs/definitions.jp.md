# 規格が定めていない動作の定義

[English](definitions.md) | [設計書](design.jp.md) | [既存版との差異](compatibility.jp.md)

SSHとSFTPの規格、およびOpenSSHとWindows OpenSSHの文書が、定めていない、未規定とする、
または実装に任せている動作のうち、本ツールが定めているものの索引である。各定義は設計書に
書き、ここには抜けている箇所、その根拠、本ツールの定めの要約だけを置く。上流の
`ssh-copy-id` と動作が違うものは、[差異一覧](compatibility.jp.md)にも載せる。この索引が
対象とするのは規格であり、上流ではない。

根拠は公開されているものを挙げる。RFC 4251〜4254、`draft-ietf-secsh-filexfer-02`（OpenSSHが
実装するSFTPの版3）、[固定した上流の比較基準](design.jp.md#固定した上流の比較基準)の時点の
OpenSSHのマニュアルである。マニュアルが何も言わずOpenSSHのソースが決めている場合はそう書く。
その動作は版によって変わり得る。

| ID | 根拠が定めていないこと | 本ツールの定め | 詳細 |
| --- | --- | --- | --- |
| U-01 | `exec` のコマンドの出力の中身。RFC 4254 §6.5・§6.6はデータとして運ぶだけで中身を定めず、§6.10は終了コードをRECOMMENDEDとするだけ。 | 登録スクリプトは接頭辞付きの結果行を出し、パスは `%XX` で符号化する。結果はこの行だけから決める。 | [登録結果](design.jp.md#登録結果) |
| U-02 | `exec` のコマンドの標準入力の区切り。RFC 4254は定めていない。 | `-t` のときは鍵の行の前に見出しを2行置く。パス、続いてその `%XX` 形式。LFを含むパスは拒否する。 | [任意の登録先](design.jp.md#記録する差異-任意の登録先の既存親ディレクトリ) |
| U-03 | `#` の前に空白がある行がコメントか。sshd(8) は「`#` で始まる行」とだけ書き、ソースは先頭の空白とタブを飛ばす。 | ソースに従い、空白とタブ以外の最初の文字で決める。 | [鍵の数え方](design.jp.md#記録する差異-鍵の数え方) |
| U-04 | authorized_keysの行末。sshd(8) は何も言わず、OpenSSH 9.6p1はCRで終わる行を受け付ける。 | 送る前にCRLFをLFにそろえる（D-05）。残すかは未決。 | [CRLFの正規化](design.jp.md#crlfの正規化) |
| U-05 | authorized_keysの文字コード。sshd(8) は何も言わない。OpenSSH 9.6p1はUTF-8のBOMで始まる行を拒み、Windows OpenSSHはファイル先頭のBOMを取り除く。 | 送る前に入力の先頭のBOMを取り除く（D-07）。 | [先頭のBOMの除去](design.jp.md#先頭のbomの除去) |
| U-06 | authorized_keysの読めない行。sshd(8) は何も言わず、ソースは解釈できない行を飛ばす。 | 読めない行、単独のCR、NULを含む入力は送る前に拒否する（D-10）。 | [CRLFの正規化](design.jp.md#crlfの正規化) |
| U-07 | `.pub` ファイルに入る鍵の数。ssh-keygen(1) とssh-add(1) は何も言わず、どちらも1行に1本を書く。 | `-i` か既定として選んだ鍵ファイルには鍵1本（D-21）。 | [選んだファイルには鍵1本](design.jp.md#記録する差異-選んだファイルには鍵1本) |
| U-08 | どの鍵で認証したか。OpenSSHのどのマニュアルもクライアントのメッセージを定めず、RFC 4252 §5.1は部分成功を定める。 | クライアント自身の `-E` ログの最初の `Authenticated to` 行を根拠にする。終了コード255と、切断メッセージを受けたログは根拠にしない。`publickey` の部分成功は受け付けられたとみなす。 | [登録済み確認に使われた鍵](design.jp.md#記録する差異-登録済み確認に使われた鍵) |
| U-09 | 終了コード255の意味。ssh(1) は「エラーが起きたら255」とだけ書き、接続先のコマンドも255を返し得る。 | 結果行の前の255は書いた可能性があるとして報告する（D-19）。255は登録済みの根拠にしない。 | [結果行の前の終了](design.jp.md#記録する差異-結果行の前の終了) |
| U-10 | SFTPの `ls -l` の一覧。draft-02 §7は `longname` の書式を定めず、クライアントは解析すべきでない（SHOULD NOT）とする。OpenSSHの `sftp` は時刻を分単位で示し、ないファイルと読めないファイルに同じ文言を出す。 | `-s`（段階3）で扱う予定。変更確認とファイルがないことの判定は、まだこの一覧に頼っており未決。 | [SFTP方式](design.jp.md#sftp方式) |
| U-11 | Windows OpenSSHがauthorized_keysのファイルに求めるACL。Microsoftの文書とWin32のソースが食い違い、文書は `StrictModes` を使えないとする一方、ソースはその下で確認する。 | Windowsの接続先（段階2）で扱う予定。検証表のW07とW08で決める。 | [権限とサービスの操作範囲](design.jp.md#権限とサービスの操作範囲) |
